# 개선 기록 (REPORT 4번 항목의 원본)

평가용 25건을 같은 조건으로 단계마다 두 번씩 측정했다. 도구 = 도구 호출 적절성, 답변 = 답변 적절성.
실행마다 답변 점수가 1건 정도 흔들려서 한 번의 1건 차이는 효과로 보지 않는다.
채점기도 같은 답변을 다시 채점하면 1건 정도 달라질 수 있다 (예: E-P-05).

## 기록표

E-R-04 평가 기준을 고친 뒤(아래 "평가셋 수정") 이전 단계도 `--rejudge`로 같은 기준에서 다시 채점했다.
표의 답변 점수는 수정된 기준이다. 괄호는 수정 전 원점수.

| baseline | — | 22 / 22 | 19 / 20 (19 / 18) | baseline*.json |
| 개선 1 | 이관 답변에 불편 인정·사유·문서 안내를 담는다 | 22 / 22 | 21 / 23 (21 / 22) | imp1_r*.json |

| 개선 3 | 답변 규칙 1단계: 주문 상태를 못 봐도 문서에 기준이 있으면 이관하지 않는다 | 24 / 24 | 21 / 21 | imp3_r*.json |

요약: 도구 호출 적절성은 88% → 96%로 올랐고, 답변 적절성은 개선 1에서 올랐다가 이후 82–92% 사이에서 흔들린다 (21–23/25).

## 평가셋 수정 (모델과 무관한 결함, 측정 후 수정)

- **E-R-04**: 필수 사실 "반품 전에 현금을 빼야 한다"는 5장에 있는데 기대 도구는 `escalate_to_agent`뿐이라, 공통 장만 읽는 에이전트는 알 수 없는 사실이었다. 기대 도구로 알 수 있는 "현금 분실 건은 상담원에게 연결한다"만 남겼다. 에이전트를 고쳐서 풀 수 없는 문항이라 평가셋을 고쳤고, 이전 측정은 재채점했다.
- 에이전트 측정 전에 채점기를 검증하면서 E-R-03, E-R-04, E-X-04의 모범 답안과 필수 사실도 한 번 고쳤다 (goldenset.json의 changelog).

## 모델 등급 비교 — 답변 모델을 terra → luna (교안이 권하는 실험)

라우터는 처음부터 luna다. 답변 모델(도구 선택·답변·이관 답변)만 한 등급 내렸고, 프롬프트·문서·평가셋은 개선 3 그대로, 채점기는 terra로 고정했다 (`ANSWER_MODEL=gpt-5.6-luna JUDGE_MODEL=gpt-5.6-terra`). 두 번씩 측정.

| 답변 모델 | 도구 (1차 / 2차) | 답변 (1차 / 2차) | 틀린 문항(도구) | 틀린 문항(답변) | 파일 |
|---|---|---|---|---|---|
| terra (개선 3) | 24 / 24 | 21 / 21 | E-S-03 | E-O-02, E-S-04, E-S-05, E-X-05 / E-O-02, E-S-02, E-S-04, E-S-05 | imp3_r*.json |
| luna | 23 / 23 | 21 / 24 | E-S-03, **E-R-05** | E-O-02, E-P-05, E-R-05, E-X-05 / E-R-05 | cmp_luna_r*.json |

- 전체 점수는 거의 같다 (차이 0–1건, 변동 범위 안). 이 평가셋에서는 luna로 내려도 점수가 눈에 띄게 떨어지지 않았다.
- **실패 구성이 다르다.** luna는 E-S-04, E-S-05를 두 번 모두 맞혔고, terra는 두 번 모두 틀렸다. 반대로 luna는 E-O-02, E-P-05, E-X-05에서 일부 실행에 틀렸다.
- **복합 문항 E-R-05는 luna가 두 번 모두 틀렸다.** "선물 포장비도 환불되나요?"는 포장 금액이 2장(주문)에, 반품 배송비가 5장에 있어 도구 둘이 필요한데, luna는 `get_return_info`만 부르고 "환불 여부는 문서에 정해져 있지 않다"며 이관했다 (terra는 둘 다 불러 맞힘). 한 건·두 번의 증거라 일반화하지는 않는다.
- 이관 문항 8건의 도구는 두 모델 모두 8/8이다.

## 정리 3 — 가정 각주를 위첨자 ᴬ로

- **이유**: `[A]`는 글자 그대로 보여 각주처럼 보이지 않았다. 문장 끝에 작게 뜨게 하려고 유니코드 위첨자 `ᴬ`(U+1D2C)로 바꿨다. 마크다운 각주(`[^A]`)는 번호로 바뀌고, HTML `<sup>`는 프롬프트에 태그가 섞여 제외했다.
- **변경**: `docs/policy.md`의 표기와 설명, 답변 규칙 2번, 데모의 가정 건수 집계(`ᴬ` 개수), README·REPORT 표기 설명. 복합 꼬리표는 `[약관 제N조]ᴬ`로 정리했다. 실제 가정 표시는 40건(설명 줄 2개 제외)이다. 앞서 문서에 적은 "42건"은 설명 줄을 포함해 잘못 센 값이어서 40건으로 바로잡았다.
- **글리프 확인**: 데모 화면에서 본문 크기와 큰 글씨 모두 작은 위첨자 A로 보였다(글자가 네모로 깨지지 않음). GitHub에서의 모양은 푸시 후 확인해야 한다.
- **측정** (`sup_r1`, `sup_r2`): 도구 23 / 23, 답변 22 / 23. 답변에 `ᴬ`나 다른 꼬리표가 새어 나온 건은 0건. 이관 문항 도구 7/7.
- 정리 2에서 도구를 건너뛰던 E-O-02는 회복됐고, 정리 1에서 보이던 E-S-04(읽고도 이관)가 다시 나왔다. 24건 환산은 도구 22·22 / 답변 21·22. 표기만 바꿨는데 한 문항씩 번갈아 움직이므로 모델이 문서 표기에 민감하다고 본다.
